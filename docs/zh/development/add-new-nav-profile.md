# 新增导航配置

导航配置是一组有名字的 Nav2 参数，用于特定场景，例如课堂演示、狭窄走廊、较快的科研测试或对比实验。

标准交付车辆不需要为了车体几何新增配置。应从已有 OSRacer 设置开始，根据环境调整导航行为。

## 什么时候需要新增配置

当场景可重复，并且明显不同于默认配置时，再新增配置：

- 低速课堂演示；
- 狭窄室内地图；
- 空旷区域较快导航；
- 障碍物较多的实验室路线；
- 对比 TEB 和 DWB；
- 需要记录参数的科研实验。

如果只是一次临时测试，优先用 launch 参数或临时 YAML，不要直接改主流程。

## 配置应记录什么

| 项目 | 需要记录 |
| --- | --- |
| 场景 | 地图、地面、障碍物密度，使用相机时记录光照 |
| Planner | TEB、DWB 或其他 controller |
| 速度策略 | 最高速度、加速度、倒车行为 |
| Costmap | inflation、障碍物范围、更新频率 |
| Recovery 行为 | 被挡住时机器人应该怎么处理 |
| 验证结果 | 日期、操作者、地图、通过/失败记录 |

## 操作步骤

1. 先确认默认导航能在同一张地图上工作：

   ```bash
   ros2 launch osracer_navigation navigation.launch.py
   ```

2. 复制最接近的参数文件，并按场景重命名。

3. 一次只改一组参数。先调速度和 costmap 保守程度，再调 planner 权重。

4. 先不运动检查：

   ```bash
   ros2 param dump /controller_server
   ros2 topic list | grep -E 'cmd_vel|plan|costmap'
   ```

5. 低速运行并在 RViz 中确认：

   - 全局路径稳定；
   - 局部轨迹没有要求车辆做不可能的转弯；
   - costmap 不闪烁；
   - 被障碍物挡住时车辆能停下；
   - 操作者可以立即停止 demo。

6. 低速可重复后，再逐步提高速度。

7. 在配置旁边记录启动命令和测试结果。

## 调参顺序

按这个顺序排查，问题会更容易定位：

1. 地图质量和定位稳定性。
2. Costmap 是否能正确看到障碍物。
3. 安全速度和加速度限制。
4. Planner 选择。
5. Planner 权重和 recovery 行为。

如果定位不稳或 costmap 不对，单纯调 planner 参数不能根治问题。

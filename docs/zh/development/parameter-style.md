# 参数风格

参数文件应该说明一个使用场景，而不是把节点支持的所有参数都堆在一起。

## 基本原则

1. 交付版机器人默认配置保持稳定。
2. 新场景使用新的 YAML 文件。
3. 硬件启动参数和导航调参参数分开管理。
4. 名称清晰优先，不要用难懂缩写。
5. 重要参数变化要记录原因。

## 文件命名

| 场景 | 示例文件名 |
| --- | --- |
| 低速课堂演示 | `nav2_classroom_slow.yaml` |
| 空旷区域较快导航 | `nav2_open_area_fast.yaml` |
| 相机标定 | `camera_calibration.yaml` |
| 底盘 EKF | `chassis_ekf_params.yaml` |
| 仿真测试 | `sim_nav2_smoke.yaml` |

## 参数注释写法

好的注释解释原因或风险：

```yaml
max_vel_x: 0.5  # 课堂演示限速；地图和定位稳定后再提高
```

不要写只重复参数名的注释：

```yaml
max_vel_x: 0.5  # x 方向最大速度
```

## 调参记录

每次修改配置时，记录这些信息：

| 字段 | 示例 |
| --- | --- |
| 机器人 | 标准交付 OSRacer 底盘 |
| 地图 | classroom_2026_06 |
| Planner | TEB |
| 速度限制 | 0.5 m/s |
| 测试结果 | 连续 5 圈未丢定位 |
| 已知问题 | 靠近玻璃墙时会减速明显 |

这些记录可以写在解释该配置的文档里，也可以写在 PR 描述里。

## Review 清单

- 默认 launch 是否仍使用安全配置？
- 其他用户能否从文件名看懂场景？
- 修改过的值是否在用户文档中说明？
- 实车运动前是否先在 RViz 中验证？
- 如果配置表现异常，是否有停车命令？
